# Appointment

## Overview
An appointment represents a client booking a service with an employee of a local, on a given date and time. Its lifecycle starts as `PENDING` or `CONFIRMED`, and ends as `CANCELLED` (manually, by the client or employee) or `COMPLETED`.

## Attributes
| Name      | Type      | Other information                                                         |
|-----------|-----------|---------------------------------------------------------------------------|
| id        | Integer   | Generated by the database (`IDENTITY`)                                    |
| date      | LocalDate |                                                                           |
| startTime | LocalTime |                                                                           |
| endTime   | LocalTime | Calculated before saving as `startTime` + the service's `durationMinutes` |
| status    | Enum      | Values: `PENDING`, `CONFIRMED`, `CANCELLED`, `COMPLETED`                  |
| client    | User      | Client who booked the appointment                                         |
| employee  | User      | Employee assigned to the appointment                                      |
| service   | Service   | Service booked; its duration sets `endTime`                               |

## Endpoints
### Base URL
`http://localhost:8080/smartBooking/smart-booking`

### Get My Appointments
`GET /appointments/me`\
Returns the upcoming appointments of the logged-in user (excluding cancelled ones), sorted by date and time. Which appointments are returned depends on the role:\
**Client / Employee:** the appointments they are part of.\
**Owner:** every appointment of their business.\
**Admin:** `403 Forbidden`.

### Cancel Appointment
`PATCH /appointments/{id}/cancel`\
`{id}`: (Integer) id of the appointment to cancel.\
Sets the appointment `status` to `CANCELLED`. The slot it occupied is released.\
Only the client or the employee of the appointment can cancel it. Any other user receives a `403`.

| HTTP Status     | Reason                                           |
|-----------------|--------------------------------------------------|
| 404 (notFound)  | No appointment exists with that id               |
| 403 (forbidden) | User is not allowed to cancel this appointment   |
| 409 (conflict)  | Appointment status is `COMPLETED` or `CANCELLED` |
| 200 (ok)        | Appointment status set to `CANCELLED`            |

### Update Appointment
`PUT /appointments/{id}`\
`{id}`: (Integer) id of the appointment to update.

| Field      | Type                 | Required | Description                                                                                    |
|------------|----------------------|----------|------------------------------------------------------------------------------------------------|
| employeeId | Integer              | No       | New employee. Must be an employee of the same business. If null, the current employee is kept. |
| date       | String (YYYY-MM-DD)  | Yes      | New date.                                                                                      |
| startTime  | String (HH:mm)       | Yes      | New start time. Date + time must be after now.                                                 |

Example:
```json
{
  "employeeId": 3,
  "date": "2026-10-06",
  "startTime": "11:00"
}
```

| HTTP Status      | Reason                                                                   |
|------------------|--------------------------------------------------------------------------|
| 404 (notFound)   | No appointment exists with that id                                       |
| 403 (forbidden)  | User is not allowed to update this appointment                           |
| 404 (notFound)   | No employee exists with the new `employeeId`                             |
| 400 (badRequest) | The new employee is not an `EMPLOYEE` of the same local                  |
| 409 (conflict)   | You can't update an appointment with status `COMPLETED` or `CANCELLED`   |
| 400 (badRequest) | Appointment `date` / `startTime` can't be null                           |
| 400 (badRequest) | You can't book on a past date or time¹                                   |
| 409 (conflict)   | The new slot overlaps another appointment                                |
| 200 (ok)         | Appointment updated with the new data                                    |

¹ "Now" counts as past: the current moment is not an available slot.

## Business Rules

### Permissions
* Only the client and the employee of an appointment can update or cancel it. This is checked right after the appointment is found, before its state, so other users don't get any information about it.
* What `/me` returns depends on the logged-in user's role.

### State
* An appointment with status `CANCELLED` or `COMPLETED` can't be updated or cancelled. Returns `409 Conflict`.
* Cancelling an appointment doesn't delete it. Its status becomes `CANCELLED`, and the slot it occupied is released.

### Date and Time
* The new date and time must be after "now"; the current moment is not an available slot.
* `endTime` is calculated as `startTime` plus the service's `durationMinutes`.

### Employee
* When updating, a null `employeeId` means the current employee is kept.
* If an `employeeId` is sent, it must exist (otherwise `404`), and it must be a user with role `EMPLOYEE` from the same local (otherwise `400`).

### Overlap
* Two appointments overlap if they belong to the same employee, are on the same date, neither is `CANCELLED`, and the one that starts first ends after the other one starts.
* When updating, the appointment is not compared with itself.

### Checking order
#### Cancel
1. The appointment exists, otherwise `404 Not Found`.
2. The user is the client or the employee of the appointment, otherwise `403 Forbidden`. This way other users don't get any information about an existing appointment.
3. The status is `PENDING` or `CONFIRMED`, otherwise `409 Conflict`.
4. The appointment is cancelled → `200 OK`.

#### Update
1. The appointment exists, otherwise `404 Not Found`.
2. The user is the client or the employee of the appointment, otherwise `403 Forbidden`. This way other users don't get any information about an existing appointment.
3. If an `employeeId` is sent, the employee exists, otherwise `404 Not Found`.
4. If an `employeeId` is sent, it belongs to a user with role `EMPLOYEE` from the same local, otherwise `400 Bad Request`.
5. The status is not `CANCELLED` or `COMPLETED`, otherwise `409 Conflict`.
6. `date` and `startTime` are not null, otherwise `400 Bad Request`.
7. The new date and time are after now, otherwise `400 Bad Request`.
8. There is no [overlap](#overlap), otherwise `409 Conflict`.
9. The appointment is updated → `200 OK`.

## Tests

### Where and how
Tests are located in `AppointmentServiceTest`. They are unit tests built with JUnit 5 and Mockito, with no database or Spring context involved: `AppointmentRepository` and `UserRepository` are mocked. Run them with `./mvnw test`.

### What they cover
* Every check of `update` and `cancel` has its own test, in the same order as the [checking order](#checking-order).
* The allowed and forbidden statuses for update and cancel, with parameterized tests over `Status`.
* The edge case of "now": a new date and time equal to the current moment is rejected.

### What they don't cover
* The overlap query (`existsOverlap`) and the `/me` queries are mocked, so they are not verified against a database. They need integration tests (`@DataJpaTest`).
* The controller and security layers don't have tests yet.
